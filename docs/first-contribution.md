# Contribute without writing code

**No coding experience required to contribute.** You need a browser and a free GitHub account to post work. You can read all tasks without an account. You do not need a terminal, installed tools, a fork or a pull request for writing, research, translation or feedback.

## Start with one task

1. Open [public information research #6](https://github.com/gsel001/one-meal-forward/issues/6), [writing #9](https://github.com/gsel001/one-meal-forward/issues/9) or [keyboard testing #24](https://github.com/gsel001/one-meal-forward/issues/24). Read the acceptance checklist, estimated effort and existing comments. These are project tasks, not food-distribution shifts.
2. If someone is already working on it, ask how to help before duplicating their work. Otherwise, comment that you would like to try it. Taking a task is voluntary; the estimate is not a deadline.
3. Do the smallest useful part. For research, check an official public source. For writing or translation, draft the text. For testing, record your browser, steps, expected result and actual result. Do not contact organizations on the project's behalf.
4. Sign in to GitHub, scroll to the comment box in the same issue, paste your findings and choose **Comment**. You can paste drafted text or translations directly. No file editing or PR is required.
5. A maintainer reviews the submission, asks any follow-up questions and explains what can be accepted. The maintainer can turn approved text or findings into repository changes. Review and merging happen later; volunteer response times vary.

A first session can be as short as reading a task and posting one useful finding. Completing the whole task may take longer.

Suggested comment format:

```text
What I checked or drafted:
Public source URL and date checked:
Finding or proposed text:
Questions or limits:
```

Use public URLs and synthetic examples only. Do not post beneficiary identities, aid applications, donor records, private contacts, internal records or sensitive screenshots. If a source is unclear, say what you could not verify. An organization website is not permission to represent it or confirm a volunteer placement.

## Review and credit

A submitted comment is not automatically accepted work. Keep replying in the same issue, and ask which criterion remains unmet if the feedback is unclear. A maintainer should preserve your authorship when preparing a file change and link to the original submission. Public recognition is optional; say if you do not want a name or quotation published. Contributor credit does not imply pay, ownership or a maintainer role.

Code changes still need a PR, tests and an authorized independent review. If you want that path, read [CONTRIBUTING.md](../CONTRIBUTING.md). If a task involves code and you only have nontechnical feedback, a useful issue comment is welcome; the code implementation remains separate.

[Ask a question in Discord](https://discord.gg/8hEQ6sJA2), [Discussions](https://github.com/gsel001/one-meal-forward/discussions) or in the task itself. Discord is optional and requires a separate account; keep submissions and decisions in the GitHub task. Do not share personal information or private records in chat. Never pay to contribute.
